# Vortex MCP read audit and update review — 29 October 2026

This bounded follow-up reviewed the combined session reader, tool-response
decoding and the Nexus/Vortex tooling's upstream and dependency versions.
It is not a repository-wide security scan or a gameplay acceptance report.

## Confirmed repairs

- Collection diagnostics accepted objects with missing fields, wrong flag types
  or negative counters as successful reads. Validate every required native and
  collection observation, retaining legitimate unknown values as `null`.
- Tool-response decoding trusted structured content without checking a supplied
  JSON text fallback. Contradictory copies now fail with
  `CONTRADICTORY_TOOL_RESPONSE`; matching copies can differ in object-key order.
  Malformed structured content is refused. This applies to snapshot reads and
  reviewed-plan acknowledgements, whose independent receipt checks remain intact.

Both regressions failed before their fixes and passed afterward. Fresh live
diagnostic observations also passed the stricter collection schema.

## Dependency advisory and compatibility

Fresh registry audit flagged the locked `@hono/node-server` 1.19.17 for
[GHSA-rmxm-3fg6-px4f](https://github.com/advisories/GHSA-rmxm-3fg6-px4f), published
to the advisory database on 28 October. It concerns repeated path decoding in
static-file serving. The guarded extension registers authenticated `/mcp` and
does not register the affected static-file route; an exploitable route in this
adapter was not established. This is a dependency advisory, not a confirmed
authentication bypass in the adapter.

MCP Node 2.1.2 already declares `@hono/node-server` range
`^1.19.9 || ^2.1.3` and uses its `getRequestListener` export. Pinning 2.1.5 stays
within that range, retains CommonJS support and Node 20 compatibility, and
includes the static-file fix. Hono and its Node adapter retain their existing
MIT license texts. Only these two runtime packages and the Vortex declaration
package changed in the lock; no new dependency family was introduced. Install
scripts and automatic host-peer installation remained disabled.

After the update, production and full registry audits reported zero known
findings across 7 and 168 dependency entries respectively. This is a dated
registry result, not proof against unknown vulnerabilities. The Vortex host's
UI/legacy peer warnings remain expected in this isolated declaration build.

## Open investigation

The live host still rejects an inventory containing a particular local DEV
record with `OPERATIONAL_VALUE_NOT_CURATED`. Bounded prefix and name-filter
queries isolated the failing record; another local DEV record reads normally.
That establishes the failure scope, not which field violates the serialization
policy. Retained preparation evidence does not prove current attribute values.
Do not normalize versions, weaken URI/secret checks, hide the record or change
Vortex metadata based only on a guessed cause. A future narrowly curated native
diagnostic should report the invalid field/type without its contents, followed
by exact regression coverage. The combined reader continues to report `partial`
and preserves its successful observations.

Native package installation remains disabled. Review the matching installed
Vortex source and prove the no-replacement boundary before expanding that API.
